# CRM REVENUE

## INPUT

- Produto ou feature
- Modelo atual de cobrança (se existir)
- Público-alvo

---

## MODELO DE RECEITA

Escolha o modelo principal (pode combinar mais tarde):

| Modelo                 | Quando usar                           |
| ---------------------- | ------------------------------------- |
| 🔄 Assinatura mensal   | Uso contínuo, previsibilidade         |
| 💳 Setup + mensalidade | Onboarding caro + uso recorrente      |
| 📦 Pacote único        | Entrega pontual, sem suporte contínuo |
| 📊 Por uso/volume      | Crescimento proporcional ao cliente   |

---

## PRECIFICAÇÃO BASEADA EM VALOR

Antes de definir preço, responda:

- Quanto o cliente perde (tempo/dinheiro) sem o produto?
- Quanto economiza ou ganha com o produto?
- O que concorrentes cobram por algo similar?

**Regra:** Preço = 10–20% do valor entregue ao cliente.

---

## ESTRUTURA DE PLANOS

Mantenha simples. Máximo 3 planos:

🥉 **Essencial** — resolve o problema core

- Features: (mínimo viável)
- Preço: R$ X/mês
- Para quem: (segmento menor, menor complexidade)

🥈 **Profissional** — resolve + escala

- Features: Essencial + (2–3 extras de alto valor)
- Preço: R$ Y/mês (2–2,5x o Essencial)
- Para quem: (segmento principal)

🥇 **Enterprise** — solução completa

- Features: tudo + suporte prioritário + customização
- Preço: R$ Z/mês ou sob consulta
- Para quem: (empresas maiores, exige maior receita)

---

## CONVERSÃO

Reduza fricção:

- [ ] Trial gratuito ou período de teste?
- [ ] Garantia de resultado ou reembolso?
- [ ] Pagamento anual com desconto?
- [ ] Onboarding incluído no plano inicial?

---

## OUTPUT

💰 Modelo: (escolhido)
📦 Planos: (3 com preço e features)
🎯 Plano principal: (o que a maioria vai contratar)
🚀 Próximo experimento: (testar uma hipótese de preço/conversão)
